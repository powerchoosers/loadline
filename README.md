# Loadline public website

The static marketing website for Loadline, a Windows browser for commercial energy consultants. It introduces the product and routes visitors to the verified public download. The Lead desk and browser tools run inside the installed application, not this website.

This repository is `powerchoosers/loadline`. Vercel serves its `public` directory at `https://loadlinehq.com`, through project `nodal-point-network/loadline`. Read `AGENTS.md` before changing the site or release metadata.

## Routes and preview

Public routes: `/`, `/features/`, `/why-loadline/`, `/how-it-works/`, `/workspaces/`, and `/download/`. Vercel rewrites both forms of each product route to `index.html`; The bundled React entry renders the matching page.

From this repository root in PowerShell, preview the actual deployment directory using the installed Vite dependency:

```powershell
node ..\browser-build\sources\workspace-ui\node_modules\vite\bin\vite.js public --host 127.0.0.1 --port 5175 --strictPort
```

Open `http://127.0.0.1:5175`. All six marketing pages use React. Run `npm ci` and `npm run build` after editing `src/`. The production bundle is committed and served from `public`, so the preview does not compile JSX at runtime. Verify the rendered routes at desktop, iPad portrait, and mobile sizes, including navigation, keyboard focus, light/dark appearance, details controls, download states, overflow, and console errors.

## Maintained sources

React sources live in `src/`: `site.jsx` owns the application, `pages.jsx` contains route content, `components.jsx` owns shared navigation, imagery, workflow, and verified downloads, and `screenshot-viewer.jsx` owns the image dialog. `feature-navigation.jsx` manages the Features section guide. `site-content.js` holds page metadata and workflow data. The FAQ uses React-rendered semantic details/summary controls.

`site.js` is generated by `scripts/build-site.mjs`; do not edit it directly. The build uses one production React runtime for the entire site, with no CDN scripts or separate nested React roots. It mirrors the bundle and license notice into `public`.

Root HTML, CSS, auth/release modules, and security configuration remain maintained sources. Mirror them before previewing or deploying:

```powershell
npm run build
Copy-Item -LiteralPath index.html,style.css,enhancements.css,auth-confirmed.html,auth-confirmed.js,auth-return.mjs,release-metadata.mjs,vercel.json -Destination public
npm test
git diff --check
```

Keep source assets and their `public/assets` copies aligned when editing assets. The real brand mark is `assets/loadline.svg`. The old supplied `assets/loadline-browser.png` is retained for history; the site now uses current app captures. Manrope is locally hosted, with its license in `assets/Manrope-license.txt`.

Root `vercel.json` defines the deployment directory, page rewrites, global security headers, Auth callback protections, the restricted browser map frame, and public update CORS/cache rules. Its copy in `public` must remain identical. Preserve those rules when adding routes.

## Feature and release accuracy

The internal feature inventory at `..\browser-build\LOADLINE-FEATURES-FOR-MARKETING.md` documents source-backed product capabilities. It does not certify that every capability is included in the current public package. Keep connected-service, permission, model, estimate, and platform limits close to the relevant feature. Do not advertise future work as shipped or treat an older product screenshot as evidence of current feature availability.

The download page reads `public/updates/latest.json`. The private browser build publishes that manifest only after the complete versioned Windows ZIP is approved and verified. Do not manually change it to announce a release or substitute a local artifact.

`release-metadata.mjs` checks the version-bound HTTPS asset URL in `powerchoosers/loadline`, Windows platform, file size, checksum shape, and publication date before the site enables a download. It permits release notes only for the same repository and version. This guards the metadata contract; it does not independently verify package contents or checksum bytes. Missing or invalid release information must leave the download unavailable with a useful status message.

Deploy through the normal Git-connected path described in `AGENTS.md`. A site change is deployed only after Vercel reports a successful production deployment for the intended commit and the production routes, assets, and manifest are checked. Website deployment does not release a new browser package.

## Product inspection and guided reading

The October 12 refinement adapts the interaction patterns from Magic UI's [Lens](https://magicui.design/docs/components/lens), [Blur Fade](https://magicui.design/docs/components/blur-fade), and [Scroll Progress](https://magicui.design/docs/components/scroll-progress) using React components, native browser APIs, and CSS. No Magic UI registry component is installed. The desktop introduction puts the copy beside the real browser image; tablet and phone layouts stack the content.

The Lens pattern helps mouse users inspect screenshots in place. It runs only with a fine pointer and hover, and magnification never exceeds the original image pixels. The fade adaptation changes opacity for 180 ms with zero blur and honors reduced motion. The four-part workflow guide is manual: familiar tabs, keyboard navigation, Previous/Next controls, and a current-step label. The Features page adds a sticky React section navigator and a reading-progress line. `src/feature-navigation.jsx` owns its disclosure menu, active section, keyboard navigation, outside-click dismissal, and focus transfer to the selected heading. The six introductory section links remain available alongside the guide. `npm run build` generates and mirrors the shared `site.js` bundle and license notice; keep those artifacts committed.

Screenshot links and Enlarge controls open an accessible native image dialog. It retains the image title, meaningful alternative text, and provenance caption, with 44 px controls, Tab/Shift+Tab containment, Escape dismissal, and focus restoration. Desktop and iPad open in Fit view. Phones open at 100% near the relevant feature so the text can be read; Fit restores the complete-image overview. At 100%, mouse users can drag to pan, while touch and keyboard users use native scrolling. The viewer contains static app screenshots.

The viewer preserves Light/Dark appearance, loading and error feedback, and an original-image link. Unmodified screenshot-link clicks open the dialog where supported; modified clicks retain the original-image link behavior, and unsupported browsers retain that fallback. Keep image sources restricted to the known local asset list and preserve Home PNG versus other WebP paths.

Verify the complete journey at the intended desktop, iPad portrait, and phone sizes. Include each workflow tab and step control, sticky section selection and progress, Light/Dark appearance, pointer inspection, Fit/100% and panning, initial phone position, keyboard containment, Escape and focus restoration, original-image links, loading/error states, reduced motion, page-scroll locking, overflow, and console health. Node tests and matching mirrors complement this rendered verification; they do not prove it.
